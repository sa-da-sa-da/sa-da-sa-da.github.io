这是一篇用于验证「新增文章 → 提交 → 推送 → 自动构建」整条链路是否正常的测试文章。它本身没有教学价值，跑通后即可删除。

## 一、这篇文章在验证什么

- **内容识别**：`content/guide/` 下的新 Markdown 能被 Hugo 正常采集，front matter 不报错。
- **URL 与分类**：`url` 使用英文 slug，分类归入「指南」，侧栏目录按 `srcDir` 归位。
- **渲染能力**：标题层级、列表、表格、代码块、引用块、站内图片均可正常显示。
- **发布链路**：`git push` 到 `main` 后，GitHub Actions 与 EdgeOne Makers 两条通道各自构建成功。

## 二、渲染自检清单

| 检查项 | 期望结果 |
| --- | --- |
| 页面可访问 | `/guide/test-article` 返回 200 |
| 标题结构 | 全页仅一个 `h1`，二级标题为 `h2` |
| 封面图 | 卡片与文章页封面均能加载 |
| 搜索索引 | 站内搜索可检索到本文标题 |
| 目录（TOC） | 右侧目录列出本文全部二级标题 |

## 三、代码块与引用块

```python
def publish_check(url: str) -> bool:
    """最简发布自检：页面能拿到就认为链路通。"""
    return url.startswith("/guide/test-article")
```

> 提示：Hugo 会静默丢弃 `date` 晚于当前时间的页面，构建日志不报错，但产物里没有该页面。排查时先用 `hugo list all` 确认页面是否被识别。

## 四、发布后的下一步

1. 打开线上地址确认页面存在且样式正常；
2. 检查首页「最新」卡片与指南分区列表是否出现本文；
3. 验证通过后删除本文件，再走一遍同样的提交流程。

如果上面每一项都符合预期，说明本次发布流程没有问题。
